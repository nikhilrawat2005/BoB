BOB DYNAMIC CACHE & DOMAIN-ISOLATED MEMORY ARCHITECTURE PLAN
================================================================================

1. THE CORE IDEA: DYNAMIC CACHE MEMORY (SWAPPING ON DEMAND)
--------------------------------------------------------------------------------
Instead of feeding Bob an ever-growing bloated context containing all past chats,
hackathons, stalker profiles, and monthly files, Bob uses a "Dynamic Cache Memory"
model that changes depending on WHERE you are chatting:

A. STALKER WORKSPACE (Single Person Context Cache)
   - When chatting about "Person A":
     -> Cache Memory loads ONLY Person A's structured card + recent messages with Person A.
     -> Person B, Person C, Hackathons, and general chats are NOT loaded.
     -> ZERO cross-contamination or leaking of other people's data.

B. HACKATHON WORKSPACE (Single Hackathon Context Cache)
   - When chatting inside "Hackathon X":
     -> Cache Memory wipes clean and loads ONLY Hackathon X's rules, dates, team,
        and problem statement + recent session messages.
     -> Other hackathons and external entities stay out of the prompt.

C. BOB MAIN CHAT (Curated Master Memory Profile)
   - Uses Master Nikhil's Clean Core Memory (user-editable points list).
   - Only includes personal facts that Master has verified or explicitly commanded
     Bob to remember.


2. MASTER MEMORY CONTROL & ZERO GREEDY EXTRACTION
--------------------------------------------------------------------------------
- Explicit-Only Memory Triggers:
  Bob will NEVER try to guess or automatically extract facts on random casual
  messages. Memory will ONLY be recorded when Master explicitly commands:
    * "Bob yaad rakh..." / "Yaad rakhna ki..." / "Yaad kar lo..."
    * "Remember that..." / "Note this down..." / "Save in memory..."
  Or when Master manually creates/edits points directly in the Memory Panel.

- All-In-One Memory Point Editor (Implemented in Step 1):
  * All past memory chunks, monthly notes, and facts are combined into a clean,
    single editable list of points.
  * Master can click ✏️ to edit inline or ✕ to delete useless points.
  * Button: "📦 Combine & Import All Stored Memory" consolidates previous auto-chunks.


3. WORKFLOW & TOKEN OPTIMIZATION BREAKDOWN
--------------------------------------------------------------------------------
Before:
  User Message -> [LLM Intent Classifier] -> [Fetch All Facts + Past Months + Hackathons + Stalkers]
               -> [Main Chat LLM Call] -> [LLM Monthly Summarizer] -> [LLM Behavior Engine]
  Total Cost: ~3,000 to 5,000 tokens per message (4+ API calls)

After (Dynamic Cache):
  User Message -> [Direct Regex Trigger Check] -> [Load Target Cache Only]
               -> [Single Lightweight LLM Call (300-600 tokens)]
  Total Cost: ~400 to 700 tokens per message (1 single API call)
  👉 Token Savings: 85% - 90% reduction! Keys last 10x longer.
